What is rspec

If the file is “abc_def.rb” the test file would be “abc_def_spec.rb”, special case is for rake task  file “abc.rake” then the test file would be “abc_rake_spec.rb” 

Tip: Should install an extension to move from a file to its test file and back quickly

Any Ruby file will match with one Rspec test file

Following the AAA (Arrange, Act, and Assert) model, I have read over our codebase and come up with some conventions here:

describe block = context block (they just alias for each other), basically create a block that contains related tests. it block is the test that we will create.

before block will do the code before every unittest, even if you declare the block last. Same idea for after block.

it_behaves_like block will insert the shared_example test into our test class.

Usually we would create a subject under our testing class like                                                                   subject { described_class.new(business_info) }

Arrange step:

instance_double is to create a double (a mock) that can mimic a class by containing their methods (so if we use one method that the class doesn't have, it will return error). double will create a double that can bypass all, so the string inside is just for labelling. 

allow(<class>).to receive(<:function>).with(<params>).and_return(<response>) useful for mocking service. Use and_raise(<error>) to create an error test.

let(:<name>) { <value> } create a temporary method with name that will return the value. let is lazy-evaluated and let! is eager-evaluated → When we need to enforce the order (for example, some value need to be created immediately before setting up with the before block) we would use let!.

 Act step:

For each unit test we can call on the function of subject to test, for example subject.call

If we were testing API, then just do a simple call <method> <path>, params: { <params> }

Assert step:

expect(<function>).condition, condition could be to eq, to be, to change, to receive. If we want the negative, include not_ before each condition, for example not_to eq not_ to be

From the subject that we declare before, check for subject.success, subject.errors, etc.

If we were testing API, check for the response code: expect(response.code).to eq '422'

The describe | context block is like an if statement, and the it block is like a then statement, for example:

context 'cat goes out'
  let ...
  let ...
  before
    (prepare something here)
    allow ...
    allow ...
  end
  
  context 'cat meets dog'
    ...
    it 'cat will fight dog'
      expect ...
      expect ...
    end
    ...
  end
  ...
end

→ Then the test would read like “If cat goes out, if cat meets dog, then cat will fight dog”

Matchers

Types of RSpec Matchers

Equality Matchers

eq: Checks if two values are equal.

eql: Checks if two objects are equivalent.

equal: Checks if two objects are the same.

Comparison Matchers

be >, be >=, be <, be <=: Compare numerical values.

Type Matchers

be_instance_of: Checks the exact class.

be_kind_of: Checks class or subclass.

Truthiness Matchers

be true: Checks if the value is true.

be false: Checks if the value is false.

be_truthy: Checks if the value is truthy.

be_falsy: Checks if the value is falsy.

Collection Matchers

include: Checks if a collection includes an element.

contain_exactly: Checks if a collection contains exactly the specified elements.

String Matchers

start_with: Checks if a string starts with a given substring.

end_with: Checks if a string ends with a given substring.

Error Matchers

raise_error: Checks for raised errors.

throw_symbol: Checks if a certain symbol is thrown.

Other Versatile Matchers

change: Checks if an operation changes an object’s state.

satisfy: Custom matcher for a specific condition.

Mastering Hash Comparisons in RSpec

When dealing with Ruby’s hash structures, precise testing becomes crucial. Here are some powerful techniques for comparing hashes in RSpec:

Exact Equality

Use the eq matcher to check for exact equality between two hashes:
expect(hash1).to eq(hash2)

Hash Inclusion

include: Verifies that a hash includes specific keys or key-value pairs.

expect(hash).to include(:key => 'value')

Key and Value Presence

have_key: Checks if a hash includes a specific key.

have_value: Checks if a hash includes a specific value.

Partial Matches

For partial matches, the match matcher can be utilized to ensure the presence of certain key-value pairs without comparing the whole hash.

Checking Empty Hashes

To verify if a hash is empty, use the be_empty matcher:
expect(hash).to be_empty
